# 5-Hour Hackathon Mode

Optimize for shipping a working demo fast.

## Workflow
- Use Superpowers only for initial writing-plans, no need for heavy brainstorming since our ideation is practically finalised for MCP. 
- After this point, do not use Superpowers brainstorming or writing-plans unless explicitly requested.
- Do not stop for design or implementation approval.
- Inspect the relevant code, make reasonable assumptions, and implement immediately.
- Prefer the simplest working implementation over ideal architecture.
- Reuse existing libraries and patterns.
- Avoid unnecessary abstractions and refactors.
- Run the smallest relevant test/typecheck/lint after changes.
- Fix errors you introduce automatically.
- Continue until the requested task works.

## Ask only if
- credentials or secrets are required
- an irreversible/destructive action is required
- the request has two fundamentally different interpretations

## Priorities
1. Working demo
2. Core user flow
3. Reliability
4. Visual polish
5. Code cleanliness
6. Architecture

Do not spend time on production-grade abstractions unless they are necessary for the demo.
